# Импорт и экспорт метаданных (v1)

В списке медиа выберите карточки → «Импорт и экспорт метаданных». Здесь доступны скачивание JSON и запись файлов рядом с оригиналами. Импорт JSON доступен также в **Настройки → Источники и импорт → Импорт и экспорт метаданных**, в том числе в пустой библиотеке.

## Когда использовать

Диалог переносит описания карточек, chips, теги, оценки, связи и временные метки между библиотеками MediaChips. Оригиналы медиа, миниатюры, настройки и подключения не копируются; для полной защиты библиотеки используйте резервные копии.

1. Для экспорта выберите карточки в списке медиа, откройте диалог через действия для выбранных элементов и скачайте `.mediachips.json` на вкладке «Экспорт выбранного».
2. В другой библиотеке откройте диалог из настроек, выберите JSON (до 50 МБ) во встроенном проводнике в папке, доступной серверу MediaChips, проверьте предварительный просмотр и разрешите каждый конфликт. Только применение импорта изменит библиотеку.
3. Для хранения метаданных рядом с медиа выберите карточки, откройте вкладку «Файлы рядом с оригиналами», отметьте форматы, проверьте пути и подтвердите запись.

**Почему экспорт недоступен из настроек?** Диалог открыт без выбранных карточек, поэтому доступна только вкладка «Импорт JSON». Для остальных вкладок откройте его из списка медиа после выбора карточек.

Справка доступна во встроенной документации по кнопке «Документация» рядом с вкладками диалога.

## Формат JSON

Расширение: `.mediachips.json`, UTF-8. Контракт и ограничения находятся в `shared/metadataTransfer.ts`, проверка столбцов и связей — в `api/services/metadataTransfer/service.ts`.

Верхний уровень: `format: "mediachips.metadata"`, `version: 1`, `exportedAt` (ISO 8601) и обязательные массивы:

- `media`: выбранные карточки; `mediaTypes`: их типы медиа;
- `fields`: определения chips (`meta`), включая тип, родителя, единицы измерения, оформление и шкалу оценки;
- `tags`: теги, включая оценки, избранное, цвет, синонимы и родительские теги;
- `mediaTags`: `{mediaId, tagId, metaId}`; `tagTags`: `{parentTagId, tagId, metaId}`;
- `mediaValues`: `{mediaId, metaId, value, rawValue}`; `tagValues`: `{tagId, metaId, value, rawValue}`;
- `marks`: временные метки с `mediaId`, `tagId`, `type`, `time`, `end`, `text`, `icon`;
- `fieldAssignments`: привязки полей к типам медиа (`metaId`, `mediaTypeId`, `scraper`, `show`, `order`);
- `fieldPins`: привязки полей к карточкам тегов (`metaId`, `pinnedMetaId`, `scraper`, `show`, `order`).

Записи сущностей содержат публичные столбцы соответствующих таблиц. `id` — положительное целое число, локальное для документа. Импорт переназначает все ID. Служебные `oldId`, состояние корзины и команды удаления файлов не переносятся. Пустые ссылки — `null`. Неизвестные версии, столбцы, неверные типы, повторные идентификаторы/связи, циклы родителей и ссылки вне документа отклоняются до применения.

Типы полей: `array`, `string`, `number`, `boolean`, `date`, `rating`. Массивы задаются ссылками на теги; значения остальных типов находятся в массивах `*Values`. Числа и логические значения представлены собственными типами JSON, даты — строками. Например, значение числового поля может иметь `"value": 1.5, "rawValue": "001.50"`, а логическое — `"value": false, "rawValue": "0"`. `rawValue` сохраняет точное исходное представление SQLite и проверяется на соответствие `value`. При редактировании JSON меняйте оба поля согласованно. Пустая строка и `null` различаются; неконвертируемое старое значение остаётся строкой. Оценки с половиной звезды и дробные времена меток сохраняются без округления.

Наследуемые от папок chips материализуются в связи выбранных карточек; правила папок не переносятся. Экспорт включает транзитивно связанные теги, их родителей, значения, chips и привязки, включая теги, используемые только в метках. Он не включает другие медиа, оригинальные файлы, миниатюры, лица, плейлисты, настройки приложения, пароли и подключения источников. Пути оригиналов сохраняются как есть: при переносе файлов в другой каталог требуется изменить пути в JSON или воспользоваться перепривязкой оригиналов в библиотеке. Отсутствие оригинала не мешает импорту JSON.

## Просмотр и разрешение конфликтов

Сопоставление выполняется по точному пути медиа, имени типа медиа, имени chips внутри того же родителя и нормализованному имени тега. Числовые ID другой библиотеки для сопоставления не используются. Неоднозначные совпадения отклоняются.

Просмотр возвращает сравнение текущих и входящих значений и связей. Он выполняется в транзакции с откатом и ничего не сохраняет. Для каждого различия требуется решение «Сохранить текущие данные» или «Заменить входящими данными». Решение для карточки/тега охватывает запись и её исходящие связи/значения; для медиа также временные метки. Непривязанные к переносимым сущностям данные библиотеки сохраняются. Привязки полей добавляются либо разрешаются отдельно при совпадении ключей.

Совпадающие имена chips с разными типами, типы медиа с несовместимым `type` и теги из другой категории блокируют импорт: измените имя в JSON или согласуйте определения. Удаление chips, наследуемых от папки назначения, также блокирует замену: сначала измените правило папки либо включите эти chips во входящие данные. Импорт не меняет тип существующего поля, поскольку это могло бы повредить значения других карточек.

Токен просмотра учитывает документ и текущее состояние совпавших записей, их связей и последовательностей ID. Изменение этих данных после просмотра требует повторного просмотра. Применение всего документа атомарно: ошибка оставляет базу без изменений. Повторный импорт того же документа не создаёт дубликатов.

## Файлы рядом с оригиналами и XMP/NFO

Выберите нужные форматы, просмотрите полные пути и нажмите «Записать проверенные файлы». Запись происходит на компьютере сервера. Поддерживаются существующие локальные оригиналы; виртуальные ZIP-записи, `nas://`, `gdrive://` и HTTP-ресурсы отклоняются. Оригиналы не изменяются.

Для `film.mp4` создаются `film.mp4.mediachips.json`, `film.xmp`, `film.nfo`. Каждый JSON содержит один оригинал с полным графом метаданных и импортируется обычным способом. Уже существующие sidecar-файлы, включая символические ссылки, блокируют запись всего набора. Совпадение путей для `film.mp4` и `film.mkv` также блокирует набор. Запись использует эксклюзивное создание; при обычной ошибке созданные этим запросом файлы удаляются. Сбой питания/процесса может оставить частичный набор; повторный просмотр покажет существующие файлы.

Проекция XMP использует [Dublin Core](https://developer.adobe.com/xmp/docs/xmp-namespaces/dc/) и [XMP Basic](https://developer.adobe.com/xmp/docs/xmp-namespaces/xmp/): название → `dc:title` (`rdf:Alt`, `x-default`), теги карточки → `dc:subject` (`rdf:Bag`), оценка карточки 0–5 → `xmp:Rating`, дата создания оригинала → `xmp:CreateDate`.

Проекция [NFO фильма Kodi](https://kodi.wiki/view/NFO_files/Movies): название → `title`, теги → повторяемые `tag`, оценка 0–5 → `userrating` 0–10 (умножение на 2), просмотры → `playcount`; `uniqueid type="mediachips"` содержит локальный ID карточки. NFO создаётся как `<movie>`; это не шаблон эпизода/аудиоальбома. Оценки вне стандартной шкалы не попадают в стандартные XML-поля.

Оба XML включают полный JSON в `mc:metadata`, пространство имён `https://mediachips.app/ns/metadata/1.0/`. Там сохраняются произвольные chips, их типы и шкалы, цвета/закладки, избранное, оценки тегов, иерархии, временные метки и все связи. У этих данных нет универсального соответствия стандартным полям XMP/NFO; сторонние приложения могут игнорировать расширение. **В этой версии обратный импорт выполняется из JSON, не из произвольного стороннего XMP/NFO.**

## API

- `POST /api/metadata-transfer/export`, тело `{mediaIds: number[]}` — JSON attachment;
- `POST /api/metadata-transfer/preview`, тело — документ; ответ `{token, counts, conflicts}`;
- `POST /api/metadata-transfer/preview-file`, тело `{filePath}` — чтение JSON из доступной проводнику папки сервера и ответ `{bundle, preview}`;
- `POST /api/metadata-transfer/import`, тело `{bundle, token, resolutions}`; ключи решений берутся из `conflicts[].key`, значения `keep`/`replace`;
- `POST /api/metadata-transfer/sidecars`, тело `{mediaIds, formats: ["json", "xmp", "nfo"]}` — список путей и токен; повторный запрос с `token` записывает файлы.

Выборка ограничена 10 000 карточек, каждый массив документа — 100 000 записей. Интерфейс принимает JSON до 50 МБ. HTTP 400 означает ошибку формата/ссылок, 409 — конфликт, отсутствие решения или устаревший просмотр. Все маршруты используют существующую защиту API приложения; ответы не кэшируются.

Проверки: `npx vitest run api/services/metadataTransfer` — перенос между реальными SQLite-базами с конфликтующими ID, все типы полей, точные значения, вложенные связи, метки, повторный импорт, решения конфликтов, откат, HTTP-контракт и запись sidecar-файлов.
