# Web video integration

In the standard build, open **Add files → Video from a web page**, paste an HTTPS video page link and choose **Add video by link**. The site adapter is selected automatically by yt-dlp, including its generic extractor for embedded videos. Supported sites depend on the installed adapter; see the [upstream site list](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md). A page must expose a combined MP4 or HLS video/audio stream. Separate DASH/video-only/audio-only formats and DRM are not supported. Playlists and channels are rejected; import a single video page. A generic HTML page containing exactly one embedded video is accepted even when yt-dlp wraps it in a playlist result.

xHamster locale, embed and legacy page URLs retain their existing normalized library identity. Other URLs preserve their path and video query parameters (for example `viewkey` or `v`), while fragments and known tracking parameters such as `utm_source` are removed. The library stores the page URL, title, duration and dimensions; playback resolves a fresh MP4 or HLS stream. Imported videos use the existing player controls, playlists and tags.

**Import options** offers path tag parsing and path exclusions, using the same parser rules as local import. Tags are parsed from the decoded path of the pasted URL before identity normalization removes its title slug. Exclusions match the pasted URL or its decoded path and prevent import. Enter one path or fragment per line. If tag assignment fails, the URL remains available for retry.

On first use, the API downloads the official standalone yt-dlp executable from `yt-dlp/yt-dlp` GitHub releases and verifies the release asset SHA-256 before installing it in the application storage `tools/yt-dlp` folder. It does not download the video file. Supported automatic installations: macOS, Windows x64, Linux x64/arm64 with glibc. Use `MEDIA_CHIPS_YTDLP_PATH=/absolute/path/to/yt-dlp` for an externally managed adapter, other platforms or offline installation. No shell commands, local yt-dlp configuration, external plugins or browser cookies are loaded. An adapter update can be installed by replacing the configured binary, or deleting the managed executable while the application is stopped; the next import resolves the current official release.

The API proxies video bytes and Range requests. HLS manifests, variant playlists, segments, initialization maps and AES key URIs are rewritten to session-bound proxy resources. Streams may use any public HTTPS CDN. Every upstream connection resolves and validates DNS, rejects private/reserved IP ranges and uses the validated address directly. Redirects and HLS resources follow the same checks. Extraction runs through a temporary loopback proxy that also checks destinations of embeds and redirects; it is closed when extraction completes or is cancelled. Page inputs require public HTTPS hostnames without credentials or custom ports. Stream URLs are not stored in the database. Short extraction caching avoids repeated resolution during startup; MP4/root streams retry extraction once on upstream authorization expiry.

The player supports seeking, buffered-range display, volume, speed, fullscreen, picture-in-picture where supported, playlists, resume time, bookmarks and marker ranges. The quality menu lists available resolutions. **Automatic** uses an HLS master when the extractor supplies one; otherwise it selects the preferred compatible stream. Changing quality and **Refresh stream** retain the playhead, pause/play intention, volume and speed without counting another view. Refresh obtains new upstream URLs and is also offered after a playback failure. Remote buffering never triggers local FFmpeg transcoding.

**Set frame as thumbnail** captures the loaded frame from the main player. Marker images can be captured at the marker's timestamp when that frame is loaded; mismatched or unfinished seeks do not save a wrong image. The API validates marker ownership, decodes/resizes JPEGs and chooses the destination inside the active library. Timeline hover shows the timestamp without starting a second network decoder. Automatic filmstrips, hover playback and local trimming require a local file and are disabled for web entries. Delete removes the library entry; there is no remote-file deletion action.

Private/login-only videos, access challenges, regional restrictions and DRM are not bypassed. Errors offer opening the original video page. Missing-file scans do not classify web video entries as lost local files. The import UI and API are disabled in SFW builds.
