# NAS: SFTP, FTP, FTPS и WebDAV HTTPS

Подключение доступно в **Добавить файлы → NAS / SFTP / FTP** и в настройках файлов. Основной сценарий — SFTP с логином и паролем.

WebDAV HTTPS использует тот же браузер, импорт, редактор метаданных и плеер. Подключение и воспроизводимая приёмка на Nextcloud и Apache описаны в [WebDAV HTTPS](webdav-integration.md).

## Подключение

1. Включите SFTP на NAS и предоставьте выбранному пользователю доступ к папке с медиа.
2. Нажмите **Добавить NAS**. Выберите `sftp`, укажите адрес NAS без `sftp://`, порт (обычно `22`), логин, пароль и абсолютный путь к папке в пространстве SFTP. Для пользователя с ограниченным корнем это может быть `/`, а не путь на диске NAS.
3. Нажмите **Проверить и сохранить**. При первом подключении приложение покажет SHA256-отпечаток SSH-ключа сервера. Сверьте его с ключом NAS и подтвердите доверие. Пароль отправляется серверу только после проверки ключа.
4. Откройте нужную папку и нажмите **▶ Смотреть без добавления в библиотеку** у видео. Плеер откроет временную потоковую сессию: файл не добавляется в БД, позиция просмотра и метки не сохраняются. Это работает и для уже добавленных файлов.

Для пакетного добавления отметьте файлы галочками и нажмите **Добавить выбранные**. Кнопка **Выбрать все** отмечает все поддерживаемые файлы в текущем списке; **Добавить все** запускает их импорт сразу. Пакетный импорт не открывает плеер. Прогресс и итог показывают добавленные файлы, повторы и ошибки; ошибка одного файла не мешает остальным. **Остановить** завершает начатые файлы и останавливает очередь. Необработанные файлы и файлы с ошибками остаются выбранными для повторного запуска. Лимит бесплатной библиотеки учитывается при добавлении.

Для NAS используется тот же компонент файлового браузера, что и для локальных файлов: навигация назад/вперёд/вверх, хлебные крошки, сортировка по имени, размеру и дате, фильтры скрытых и неподдерживаемых файлов и файлов в библиотеке. Кнопка обновления перечитывает папку и статусы импорта. Теги локальных папок в NAS не показываются.

В **Параметрах импорта** доступен тот же парсинг тегов, что и для локальных файлов: поиск существующих тегов и извлечение по регулярным выражениям категорий. Парсер получает полный читаемый путь на NAS, без служебного `nas://` и ID подключения. Опция **Исключить определённые пути** принимает пути или фрагменты по одному на строку; соответствующие файлы и вложенные папки пропускаются до импорта. При ошибке назначения тегов файл остаётся выбранным для повторного запуска.

Выбор сохраняется при переходе между папками одного подключения. Можно отметить папки галочками или выбрать текущую папку кнопкой на панели: перед импортом приложение обходит вложенные папки, пропускает уже добавленные версии и объединяет повторные пути. Скрытые файлы и папки включаются только при включённой опции показа скрытых. Поиск можно остановить, сохранив исходный выбор; при остановке пакетного импорта остаются необработанные файлы. Недоступные и ограниченные первыми 5000 элементами папки остаются выбранными с ошибкой для повторного запуска. Кнопка добавления всех файлов в списке относится только к видимым файлам текущей папки.

Для SFTP также доступен приватный SSH-ключ с необязательной парольной фразой. FTP использует логин и пароль; FTPS — явный TLS, обычно на порту `21`, с проверкой сертификата. Самоподписанный сертификат должен быть доверенным для серверного процесса. Перехода с FTPS на незашифрованный FTP при ошибке нет.

## Воспроизведение и библиотека

- Видео читается с NAS через локальный API во время просмотра. HTTP Range поддерживает перемотку; полная загрузка файла перед стартом не требуется.
- SFTP, FTP и FTPS распознают те же форматы, что и Google Drive: видео MP4, M4V, MKV, AVI, WMV, ASF, MOV, WebM, MPEG/MPG, FLV, MTS/M2TS/TS, VOB, 3GP/3GPP/3G2, OGV, MXF, RealMedia и другие контейнеры; аудио MP3, M4A, AAC, WAV, OGG, FLAC; изображения JPG/JPEG, PNG, GIF, WebP, AVIF, BMP. Импорт и передача используют общий список расширений и MIME-типов. Воспроизведение видео и аудио зависит от кодеков браузера/Electron; удалённое перекодирование не реализовано.
- Изображения открываются напрямую через API как из файлового браузера без импорта, так и из библиотеки. Для импортированных изображений сохраняется проверка версии файла. Изображения не получают видеометаданные; аудио и видео импортируются в свои типы медиа.
- При открытии добавленной карточки из библиотеки метки, позиция просмотра, постеры и снимки для меток сохраняются. Постеры и снимки берутся из воспроизводимого кадра. Длительность и размеры видео записываются после загрузки его метаданных плеером. Во временном просмотре из файлового браузера доступны воспроизведение и перемотка, а действия редактирования библиотеки скрыты.
- Отключение удаляет сохранённые учётные данные и останавливает активные NAS-запросы; карточки и метки остаются. Для восстановления доступа откройте **Учётные данные**, введите пароль и сохраните подключение.
- Изменение сервера, аккаунта или корневой папки требует нового подключения. Название и учётные данные существующего подключения можно обновлять.
- При редактировании форма показывает, сохранён ли пароль или SSH-ключ. Пустое поле оставляет прежние учётные данные и зашифрованный файл без изменений. Значок глаза показывает только вводимый пароль; сохранённые секреты API не возвращает. Чтобы заменить пароль, введите новый и сохраните подключение.
- Версия файла определяется размером и временем изменения. Если они изменились, старую карточку нельзя воспроизвести до добавления новой версии отдельной карточкой. Замена с прежними размером и временем изменения этим механизмом не обнаруживается.
- Сканирование отсутствующих локальных файлов пропускает NAS-карточки. Удаление карточки не удаляет файл с NAS. Символьные ссылки в списке скрыты; выход из выбранного корня запрещён.

## Хранение и перенос

Таблицы `sourceConnections` и `mediaLocations` хранят настройки сервера и связь с карточкой. `media.path` содержит идентификатор вида `nas://...`, без пароля. Миграция `0032_media_sources` добавляет таблицы без изменения локальных путей.

Пароли и SSH-ключи шифруются AES-256-GCM в папке `nas-secrets` рядом с данными приложения, вне библиотеки и статических HTTP-каталогов. На Unix папка имеет права `0700`, файлы — `0600`. Ключ шифрования находится на этом же компьютере в `master.key`; это защита хранения средствами файловой системы, **не системная связка ключей**. Для управляемого запуска можно задать 32-байтовый ключ в base64 через `MEDIA_CHIPS_NAS_SECRET_KEY`.

Экспорт/слияние библиотек сохраняет карточки и расположения, но не переносит учётные данные. На другом компьютере пароль нужно ввести заново. Не публикуйте папку `nas-secrets` и не включайте её в экспорт библиотеки.

## Проверки

Тесты сервиса проверяют импорт без дублей, изменённые версии, отключение, смену библиотеки, слияние карточек, хранение секретов и HTTP Range/HEAD/If-Range. Тесты транспорта используют локальные SFTP- и FTP-серверы: вход с паролем, проверка SSH-ключа до аутентификации, Unicode-пути, фильтрация ссылок, ограниченное чтение и отсутствие отката FTPS к FTP. Подключение к конкретному NAS пользователя проверяется отдельно.

Браузерная проверка Chromium на изолированной временной библиотеке прошла полный сценарий SFTP: подтверждение ключа, вход с паролем, просмотр папки, импорт, воспроизведение, перемотка, сохранение постера и кадра новой метки. Проверены обычная и SFW-сборки.

Пакетный импорт отдельно проверен в Chromium на 13 файлах: выбор нескольких, добавление всего списка, остановка после начатых файлов, продолжение оставшихся и повторный импорт без дублей. Тесты очереди и API проверяют частичные ошибки, отмену, смену библиотеки, ограничения размера запроса и доступную ёмкость библиотеки.
