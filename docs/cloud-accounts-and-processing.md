# Облачные аккаунты и тяжёлая обработка

В «Источниках» вкладка **OneDrive · Dropbox · Google Drive** позволяет добавить несколько независимых аккаунтов каждого провайдера. Старое подключение Google Drive и `gdrive://file-id` продолжают работать.

## Подключение

Создайте OAuth-приложение у провайдера и зарегистрируйте точный Redirect URI, показанный в форме: `http://localhost:12321/api/cloud-accounts/oauth/callback` для стандартного локального сервера. Для удалённого сервера укажите его HTTPS-адрес с тем же путём. Client ID/App key и при необходимости Client secret вводятся отдельно для каждого подключения.

OneDrive использует Microsoft Graph с delegated `Files.Read` и `offline_access`; для личных и рабочих аккаунтов приложение должно разрешать соответствующие типы аккаунтов. Dropbox-приложению нужны `files.metadata.read` и `files.content.read`; объём доступных папок определяется выбранным в консоли типом доступа. Google Drive использует `drive.readonly`. Все три подключения запрашивают код авторизации с PKCE S256, одноразовым state и сроком входа десять минут.

После сохранения нажмите «Подключить», завершите вход в открытом окне и нажмите «Обновить». Выберите файлы и воспользуйтесь общей кнопкой импорта. Расширения и исключения из формы импорта применяются к файлам; выбранные файлы импортируются последовательно. Папки открываются для просмотра, их рекурсивный импорт выполняется существующим каталогом источников через API. Поддерживаются постраничные списки, технические метаданные, изображения, аудио и Range-просмотр видео. Длительность и размеры видео заполняются, если провайдер вернул эти поля.

Стабильный путь имеет вид `onedrive://<connection-uuid>/<encoded-object-id>`, `dropbox://…` или `gdrive://<connection-uuid>/<encoded-object-id>`. Токены и адреса скачивания в нём отсутствуют. Смена названия карточки, рейтинг, чипы и метки не перезаписываются повторным импортом. Отключение одного аккаунта не затрагивает другие. Новые аккаунты доступны общему каталогу, офлайн-кешу и чтению проверенных копий; запись в облачные оригиналы отключена.

Для воспроизведения карточки `/playable` выдаёт URL со случайным идентификатором сессии, действительным до шести часов. Сессия закрепляет библиотеку, карточку, расположение и наблюдаемую версию оригинала. Каждый запрос, включая перемотку, сверяет версию и размер до чтения и повторно перед отправкой байтов. Изменение файла возвращает `409 source_version_changed`, а повторный вход, отключение аккаунта или истечение сессии требуют нового URL. Смена библиотеки или расположения не позволяет использовать старую сессию. Старое подключение Google Drive использует тот же контракт. Проверка опирается на версии провайдера, а не на полный хеш содержимого. Офлайн-копии продолжают открываться отдельным URL без подключения к облаку.

Конфигурация OAuth и токены хранятся через AES-256-GCM в host-local `cloud-accounts` под `MEDIA_CHIPS_DATA_DIR` (либо каталогом приложения). Они не попадают в базу медиатеки и резервные копии. На другом компьютере выберите существующий аккаунт, нажмите «Настроить аккаунт», заново укажите OAuth Client ID/секрет и выполните вход: ID подключения и существующие карточки сохраняются. Авторизацию можно восстановить после перезапуска процесса, незавершённый OAuth-вход нужно начать заново.

## Пакеты обработки

- `packages/processing-core` — общая очередь, лимиты и запуск FFmpeg без shell.
- `packages/remote-transcode` — серверная MP4-копия облачного оригинала, H.264/AAC, до 1280 пикселей по ширине.
- `packages/background-storyboard` — JPEG-сетка 4×3 с заданным интервалом выборки от начала видео; для короткого видео сетка может быть неполной.
- `packages/frame-extraction` — JPEG заданного момента, до 1280 пикселей по ширине.

Это обработка удалённых оригиналов на сервере MediaChips. Отдельный внешний вычислительный сервис не требуется. Файл сначала скачивается в ограниченное временное хранилище, затем FFmpeg читает только локальный сгенерированный путь. OAuth-токены не передаются FFmpeg. Версия и размер источника проверяются до и после скачивания.

В панели обработки выберите ID импортированного видео, вид задачи и параметры. Задачи доступны после закрытия панели, пока работает сервер. Процессная очередь общая для всех библиотек: одна активная задача, до 16 ожидающих, два потока FFmpeg, десять минут на скачивание и обработку, до 2 GiB входных данных и 512 MiB результата. FFmpeg ограничивает отдельное выделение памяти 128 MiB и декодируемый кадр 16 мегапикселями. Контроль RSS завершает процесс при превышении 768 MiB (проверка раз в 500 мс через системный ps / PowerShell; это мониторинг, а не жёсткий OS sandbox). Параметры задаются `ProcessingLimits` при создании сервиса. Максимум 32 записи задач ограничивает также хранение результатов; завершённые задачи можно удалить вручную. Исходники никогда не изменяются.

Результат доступен 30 минут через авторизованный API; после истечения срока удаляется при очистке. Задачи и результаты временные: очередь не возобновляется после перезапуска. Изменение исходного пути/версии карточки блокирует выдачу устаревшего результата. Переключение библиотеки не позволяет получить результат из другой библиотеки.

## API

`/api/cloud-accounts`: GET — список аккаунтов, POST — создание. Для `/:id`: POST `/oauth/start`, POST `/logout`, PUT `/configuration` — повторный ввод OAuth-конфигурации без смены ID/провайдера, GET `/files?key=root&pageToken=…`, GET `/metadata?key=…`, POST `/import` с `{key}`, GET `/stream?key=…`. Общий callback — GET `/oauth/callback`. Для карточки: GET `/media/:mediaId/playable`, GET `/media/:mediaId/stream`, POST `/media/:mediaId/frame`.

`/api/remote-processing`: GET `/limits`, GET/POST `/jobs`, GET/DELETE `/jobs/:id`, POST `/jobs/:id/cancel`, GET `/jobs/:id/result`. Тело создания: `{mediaId, kind: "transcode" | "storyboard" | "frame", seconds?, intervalSeconds?}`. Результаты доступны только в контексте исходной библиотеки.

## Приёмка

Результаты приёмки OneDrive/Dropbox, ограничения среды и изолированный live-стенд: [onedrive-dropbox-acceptance.md](onedrive-dropbox-acceptance.md). Оба провайдера сохраняют beta-статус до живой приёмки.

`api/services/cloudAccounts/acceptance.test.ts` выполняет один HTTP-сценарий для Google Drive, OneDrive и Dropbox: создание двух аккаунтов, OAuth/PKCE и защита от повторного callback, список, метаданные, идемпотентный импорт, сохранение пользовательских полей, просмотр byte range, отключение и восстановление аккаунта после перезапуска. Провайдерские HTTP-транспорты заменены фикстурами; реальные ключи не нужны. `providers.test.ts` проверяет формат запросов, страницы, ошибки, отмену и отсутствие Graph-токена в CDN-запросе.

`processing.test.ts` запускает настоящий FFmpeg и проверяет все три производных результата, удаление временных исходников, лимит входного файла и изменение версии. Тесты очереди проверяют конкурентность, переполнение, отмену и тайм-аут. Браузерный сценарий — `e2e/cloud-accounts.spec.ts`.

Для live-приёмки повторите подключение, импорт, проверку размера/длительности и просмотр с перемоткой для каждого провайдера с реальными ключами и двумя аккаунтами. Автоматические тесты не подтверждают настройки OAuth-приложений и доступность внешних сервисов.

Официальные контракты: [Microsoft Graph: список файлов](https://learn.microsoft.com/en-us/graph/api/driveitem-list-children?view=graph-rest-1.0), [Microsoft Graph: скачивание и Range](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0), [Dropbox HTTP API](https://www.dropbox.com/developers/documentation/http/documentation), [Dropbox OAuth](https://docs.dropboxapi.com/dropbox-api/docs/oauth).


## Метаданные и фоновое заполнение

Импорт одиночных файлов, повторный импорт и обновление каталогов сохраняют доступные технические метаданные провайдера. Это работает и для старого подключения Google Drive (`gdrive://file-id`). Google Drive и Dropbox могут возвращать длительность и размеры видео, а также размеры изображений. OneDrive дополнительно передаёт доступные FPS, битрейт, кодек и аудиотеги. Все поля зависят от ответа провайдера: неподдерживаемые и ещё не обработанные значения остаются пустыми.

Через пять секунд после запуска API начинается фоновый обход активной библиотеки, по 16 записей за проход с интервалом десять секунд и максимум двумя параллельными запросами. По завершении обход повторяется через 15 минут, чтобы забрать отложенные данные или повторить запросы к недоступным источникам. После перезапуска приложения обход начинается заново; переключение библиотеки проверяется перед записью. Удалённые в корзину и локальные файлы не участвуют.

Фоновая задача и обновление информации на карточке используют только API метаданных — оригиналы не скачиваются. Заполняются только пропуски; известные технические значения, название карточки, оценки, чипсы, маркеры и позиция просмотра сохраняются. Ответ от другой версии оригинала не применяется. Для полей, которые провайдер не отдаёт (например, кодека у Google Drive), автоматический анализ видео через FFprobe не запускается.


Открытые облачные карточки, карточки на главной странице и инспектор обновляются автоматически: раз в пять секунд клиент читает только сохранённые метаданные незаполненных карточек через `/api/cloud-accounts/metadata/snapshot` (до 64 ID за запрос). Запросы не запускают облачный анализ и не загружают теги или весь список медиа. После заполнения полей опрос этих карточек прекращается; скрытая вкладка и заблокированное приложение опрос не выполняют. Список и прокрутка сохраняются, ответы от прежней библиотеки/сервера отбрасываются, а изменения пользователя во время запроса имеют приоритет.

## Метаданные и обложки NAS

Для NAS (SFTP, FTP, FTPS и WebDAV) фоновая задача заполняет пропущенные технические данные уже добавленных видео, аудио и изображений и сохраняет JPEG-обложки в локальный кеш библиотеки. Доступные поля включают длительность, размеры, FPS, битрейт, кодек и аудиотеги. Для видео извлекается кадр, для изображений создаётся миниатюра, для аудио используется встроенная обложка. Отсутствие встроенной обложки запоминается. Известные значения и пользовательские обложки сохраняются.

Обход начинается через пять секунд после запуска сервера, проверяет до 32 карточек за проход с интервалом десять секунд и обрабатывает один NAS-файл за раз. Новые карточки подхватываются очередным проходом. Недоступные источники и незаполненные поля повторно проверяются через 15 минут. Очередь отменяется при завершении сервера; смена библиотеки, расположения, версии файла или настроек подключения блокирует запись устаревшего результата.

FFprobe и FFmpeg читают нужные диапазоны через временный адрес только на loopback-интерфейсе; реквизиты NAS в аргументы процессов не передаются. Полный оригинал предварительно не скачивается. На анализ отводится до 32 MiB чтения, на обложку — до 64 MiB, на одну задачу — до 100 секунд. Если формат требует большего объёма или не поддерживается, неизвестные поля остаются пустыми; уже полученные метаданные сохраняются даже при неудаче создания обложки.

Карточки NAS, главная страница и инспектор используют тот же локальный snapshot раз в пять секунд. После появления метаданных и обложки они обновляются без перезагрузки страницы. Опрос не обращается к NAS. Изображения в карточках используют локальные миниатюры; полноразмерный просмотр продолжает открывать оригинал.

`api/services/nas/mediaAssets.test.ts` проверяет обработку настоящими FFprobe/FFmpeg: видео с индексом в конце файла и чтением диапазонов, изображения, аудио со встроенной обложкой и без неё, повторные попытки, лимит чтения, сохранение пользовательских данных и отмену при изменении источника. Транспортные тесты отдельно проверяют NAS-протоколы; live-приёмка на реальном NAS остаётся отдельной проверкой подключения.
