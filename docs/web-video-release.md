# Веб-видео: границы поддержки и приёмка

Дата: 2026-10-21. Матрица основана на `shared/webVideo.ts`, `html5.ts`,
`ytDlp.ts`, `service.ts` и `src/services/webVideoPlayback.ts`.
Это поддержка форматов и способов извлечения, а не любых сайтов.

| Сценарий | Поддержка | Подтверждение |
| --- | --- | --- |
| Одна публичная HTTPS-страница со статическим HTML5 video/source | MP4 и HLS; относительные ссылки и base; без исполнения JavaScript | Тесты HTML5; прежняя живая приёмка W3C MP4 |
| Динамическая страница/встраиваемый плеер | Условно: адаптер установленного yt-dlp должен извлечь один совместимый поток | Тест запуска yt-dlp через защищённый прокси; живой прогон не выполнен |
| MP4 с совмещёнными звуком и видео | Проксирование, Range, перемотка при поддержке диапазонов источником | Тесты 206 и зеркала; прежняя живая приёмка W3C |
| HLS VOD | Переписывание master/media playlist, сегментов, initialization map и AES key; native HLS или hls.js | Тесты парсинга и проксирования; живое воспроизведение HLS не подтверждено |
| Качество | Фиксированное разрешение либо адаптивный HLS master, если доступен | Модульные тесты выбора и сохранения качества |
| Истёкший корневой URL | Одно повторное извлечение при 401/403/410; качество сохраняется | Мок-тесты обновления URL |
| Истёкший сегмент/ключ HLS | Автоматическое переизвлечение сегментов не заявлено; Refresh stream | Ограничение реализации; нужен живой прогон |
| Обрыв и восстановление | Ошибка потока; повторное открытие/Refresh stream; позиция сохраняется плеером | Прежний живой W3C MP4-прогон с управляемым обрывом; не новая приёмка этой правки |
| Неподдерживаемый сайт, отказ извлечения, CAPTCHA/403 | Понятная ошибка без stderr; карточка при неудачном импорте не создаётся | Мок-тесты отказов и блокировки |
| DRM, отдельные video/audio, DASH, плейлисты/каналы | Не поддерживаются этим трактом | Тесты отклонения |
| Cookies пользователя, вход на сайт, paywall, CAPTCHA, live/DVR | Не заявлены; обход ограничений отсутствует | Живая приёмка отсутствует |
| HTTP-страница, внутренний хост/IP, нестандартный порт | Отклоняются на входе; медиа требуют публичного HTTPS | Проверки URL/DNS, редиректов и SSRF |

Импорт сохраняет адрес страницы и идентичность карточки. Подписанные адреса
медиаресурсов остаются в памяти сервера; плеер получает адрес сеанса приложения.
Не вставляйте секретные ссылки страниц как постоянные адреса библиотеки:
сам адрес импортированной страницы сохраняется. Открытие страницы в браузере
может работать, когда извлечение запрещено сайтом. Обновление адаптеров не
гарантирует поддержку сайта. В частности, полная поддержка YouTube может требовать
дополнительного JS runtime и yt-dlp-ejs, которые этот тракт не настраивает.

## Управляемый yt-dlp

При первом обращении динамического извлечения устанавливается бинарник; при
последующих обращениях проверка обновления выполняется после 24 часов с последней
успешной установки. HTML5-путь не требует yt-dlp. Используется только latest release
официального `yt-dlp/yt-dlp` через GitHub API. Требуется SHA-256 digest ассета;
при его отсутствии установка запрещена. Метаданные не следуют редиректам;
скачивание допускает лишь HTTPS GitHub и его release CDN, без системного proxy.
SHA-256 сверяется до записи. Контрольная сумма доверена официальному HTTPS API;
это не независимая проверка GPG-подписи и не защита от компрометации самого upstream.

Новый файл записывается рядом со старым с уникальным именем и заменяет его через
rename. При ошибке сети, хеша или замены старый файл остаётся доступен; временный
файл удаляется. Map блокирует параллельные обновления одного пути внутри процесса,
эксклюзивный `.lock` — между процессами. Другой процесс использует старый бинарник,
а если его ещё нет, установка завершится безопасной ошибкой и её можно повторить.
После аварийного завершения `.lock` не удаляется автоматически: остановите все
экземпляры MediaChips и удалите только этот lock в tools/yt-dlp. Это исключает
удаление блокировки работающего обновления по ненадёжному тайм-ауту.

Управляемые ассеты: macOS x64/arm64 (`yt-dlp_macos`), Windows x64 (`yt-dlp.exe`),
Linux x64 (`yt-dlp_linux`) и arm64 (`yt-dlp_linux_aarch64`). Требования ОС/libc
определяет официальный бинарник; совместимость установщика на всех этих ОС
в этой сессии не проверялась. Windows может запретить замену занятого executable:
сохранится старый файл, обновление повторится при следующем обращении.
`MEDIA_CHIPS_YTDLP_PATH` имеет приоритет на любой платформе: такой бинарник
приложение не скачивает, не проверяет и не заменяет; обновляет его пользователь.

Официальные сведения: https://github.com/yt-dlp/yt-dlp#release-files и
https://github.com/yt-dlp/yt-dlp#dependencies.

## Проверки этой правки

Тесты используют временные каталоги и библиотеки, моки HTTP/извлечения.
Проверены контрольная сумма, адрес upstream и редирект, успешная замена,
параллельные вызовы, межпроцессный lock, отказ rename, сохранение старого файла,
внешний executable и платформы. Существующие тесты проверяют HTML5, HLS,
Range, переизвлечение истёкшего корневого URL, отказы и отсутствие дублей.

Прямой сетевой запрос `api.github.com` в этой среде завершился ошибкой DNS
`Could not resolve host`. Скачивание реального executable, динамический сайт
и живой HLS в этой сессии не пройдены. Сетевая проверка CONNECT требует разрешения
на локальный listen; здесь возвращается EPERM. Она не отмечена пройденной.
Предыдущая реальная приёмка и её артефакты описаны в
[отчёте](release-blockers-remote-sources.md); к новому коду обновления она не относится.

Перед снятием условного статуса нужны прогоны установленной сборки на целевых ОС:
установка/обновление официального бинарника, одна согласованная публичная
динамическая страница и HLS VOD с перемоткой, истечением сегмента и восстановлением.
Проверять в отдельной библиотеке; не сохранять подписанные URL в отчётах.

Итог локальной регрессии: 108 тестов прошли (80 извлечения/библиотеки/кадров/URL и 28 сетевых), один тест CONNECT исключён после EPERM. ESLint изменённых TypeScript-файлов прошёл. Общая проверка типов API блокируется существующими ошибками JSON imports в `chipRecipe.test.ts` и unknown в `cloudAccounts/accounts.test.ts`; ошибок изменённых файлов не осталось.
