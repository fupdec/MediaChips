# WebDAV HTTPS

WebDAV подключается в **Источники → NAS / SFTP / FTP / WebDAV → Добавить подключение**. В протоколе выберите **WebDAV HTTPS**. Укажите имя сервера без `https://`, порт (по умолчанию 443), логин, пароль и корневой путь WebDAV без URL-кодирования.

Для Nextcloud адрес `https://cloud.example/remote.php/dav/files/USERNAME/` задаётся как сервер `cloud.example`, порт `443`, корень `/remote.php/dav/files/USERNAME/`. Если Nextcloud установлен в подпапке, включите её в корень. Используйте пароль приложения из настроек безопасности Nextcloud. См. [документацию Nextcloud](https://docs.nextcloud.com/server/latest/user_manual/en/files/access_webdav.html).

**Проверить и сохранить** проверяет доступ к корневой папке. После подключения доступны переходы по папкам, размеры и даты файлов, предпросмотр без импорта, рекурсивный и пакетный импорт. Импорт создаёт обычную карточку библиотеки: название, рейтинг, избранное, заметки и теги редактируются существующим редактором. Эти метаданные хранятся в библиотеке MediaChips и доступны при отключённом WebDAV. Плеер читает оригинал через API и поддерживает HTTP Range для перемотки. Скачивание использует тот же поток; полный файл перед воспроизведением не загружается. Поддерживаемые форматы и ограничения кодеков совпадают с остальными NAS-источниками.

Транспорт реализует `list`, `stat`, `read`, `close` существующего адаптера источников. Данные соединения хранятся как провайдер `nas`, протокол `webdav`; пути карточек используют существующий `nas://` с ID подключения и версией. Миграция БД не нужна. Список и сведения читаются через PROPFIND Depth 1/0 по [RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html), содержимое — через GET. ETag входит в версию файла; изменение версии требует нового импорта и не переиспользует старые временные метки. При наличии сильного ETag чтение защищено If-Match от изменения файла между проверкой и GET.

Пароль находится в существующем шифрованном хранилище NAS вне БД. Соединение использует только HTTPS с проверкой сертификата; перенаправления допускаются лишь на тот же origin внутри корня. При собственном центре сертификации укажите CA серверному процессу через `NODE_EXTRA_CA_CERTS=/absolute/path/ca.pem` до запуска. Отключения проверки TLS и перехода на HTTP нет. Basic Authentication подходит для логина и пароля приложения; Digest и OAuth этого транспорта не реализованы. Перемещение и удаление удалённых файлов недоступны.

## Воспроизводимая приёмка

Нужны Docker Desktop, Node.js, зависимости проекта, OpenSSL и установленный Chromium Playwright. Стенд запускает настоящий Nextcloud (SabreDAV) и независимый Apache mod_dav. Apache также завершает TLS перед Nextcloud. Порты 18443/18444 привязаны только к loopback; пользователь `reader` и пароль `webdav-acceptance-password` предназначены исключительно для этого одноразового стенда.

```sh
node scripts/webdav-fixture/setup.mjs
WEBDAV_ACCEPTANCE=1 NODE_EXTRA_CA_CERTS="$PWD/.cache/webdav-acceptance/cert.pem" \
  npx vitest run api/services/nas/webdav.integration.test.ts
WEBDAV_ACCEPTANCE=1 npx playwright test --config playwright.webdav.config.ts
node scripts/webdav-fixture/setup.mjs down
```

API-тест использует отдельную временную SQLite-библиотеку; браузерный тест запускает отдельный процесс приложения на порту 18445 с временной библиотекой и собственным хранилищем паролей. Работающая пользовательская библиотека не используется. Браузерный тест собирает приложение и backend перед запуском. Опциональные приёмочные тесты пропускаются без `WEBDAV_ACCEPTANCE=1`; отсутствие стенда не считается успешной приёмкой. Сертификат стенда действует 7 дней; после истечения остановите стенд и удалите `.cache/webdav-acceptance/cert.pem` и `key.pem` перед новым setup.

API-сценарий на каждой реализации проверяет подключение, Unicode/пробелы/`%`/`#` в путях, листинг и сведения, предпросмотр, пакетный импорт и дубли, реальный API редактора метаданных, побайтовое равенство чтения и Range, HEAD, 416, скачивание, сохранение пароля при редактировании, отключение и восстановление той же карточки. Браузерный сценарий проверяет форму подключения, папки, реальное декодирование видео и перемотку до и после импорта, сохранение заметки через редактор и переподключение. Скриншоты браузера, редактора и плеера сохраняются в `test-results/`; при ошибке сохраняется trace.

## Результат приёмки 2026-10-16

Сценарии API и браузера успешно выполнены на **Nextcloud 32.0.15 (SabreDAV)** и **Apache 2.4.69 (mod_dav)** с проверкой TLS по CA стенда. Оба браузерных E2E-теста прошли, включая декодирование MP4, перемотку до и после импорта, сохранение/повторное открытие заметки и восстановление подключения без создания новой карточки. Временные серверы после проверки остановлены и удалены.

Также прошли 87 проверок транспорта, общего адаптера, библиотеки и API (включая две проверки на настоящих серверах) и 57 проверок интерфейсной логики импорта/браузера. Сборка Vite, проверка типов frontend и production backend успешны. Приёмочные скриншоты создаются в `test-results/webdav-https-*`.
